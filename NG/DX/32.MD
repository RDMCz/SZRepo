> Jazyk XML – základní principy a pravidla. Definice jazyka a validace dokumentu.

## Jazyk XML

Jazyk XML (_eXtensible Markup Language_) je jazyk popisující strukturu dat. Cílem je jednotný mechanismus a obecné nástroje pro kontroly, konverze apod. Jedná se o podmnožinu [SGML](https://web.archive.org/web/20160422151019/https://www.eprg.org/computerphile/newsgml.pdf) – jednodušší, snažší implementace, rychlé rozšíření, přijato W3C. Zároveň se jedná o metajazyk (lze v něm definovat další jazyky), který definuje:

* Základní syntaktická pravidla dokumentů
* Nástroje pro popis prvků jazyka a jejich vztahů

```xml
<?xml version="1.0" encoding="UTF-8"?>  <!-- „PROLOG“, deklarace jazyka a kódování; nepovinné -->

<alba>  <!-- KOŘENOVÝ PRVEK; povinné -->

    <disk id="disk1">  <!-- BĚŽNÉ PRVKY -->
        <interpret>Kraina Mroku</interpret>
        <nazev>Przyjdź Królestwo Moje</nazev>
    </disk>

</alba>
```

* XML definuje strukturu dokumentu
* Obecné XML nástroje umožňují zkontrolovat dokument nebo jej transformovat do libovolného jiného formátu
* XML nic neříká o sémantice – významy prvků musí znát aplikace
* Struktura, pravidla:
  * Dokument je rozdělen do prvků
  * Prvek se zapisuje tagem `<tag>...</tag>`, jména prvků jsou case sensitive
  * Mezi tagy se nachází obsah prvku
  * Prvky lze vnořovat, nesmí se křížit
  * Prázdný prvek lze zapsat jako `<tag></tag>` nebo `<tag />`
  * Celý dokument je vždy zabalen do jednoho kořenového prvku, který je pro daný jazyk pevně definován, např. `<html>`
  * Prvku lze doplnit další informace pomocí atributů `<tag nazev-atributu="hodnota-v-uvozovkach">obsah</tag>`
  * Speciální znaky vyjadřujeme ve formátu `&lt;`, `&gt;`, `&amp;` atd.
  * `<!--Komentáře-->` jsou při zpracování dokumentu ignorovány
  * `<?Komu Co?>` jsou dodatečné informace pro zpracující program, nejsou považovány za součást struktury dokumentu
  * `<![CDATA[...]]>` slouží pro označení obsahu, který nemá být interpretován (pouze opsat beze změny), vhodné např. pro ukázky XML kódu uvnitř XML dokumentu

Tzv. _well-formed_ dokument je takový dokument, který dodržuje syntaktická pravidla XML – týká se formy, nikoliv obsahu/struktury. Nutný předpoklad pro zpracování jakýmkoliv XML nástrojem.

Tzv. _valid_ dokument je takový dokument, který je _well-formed_ a struktura jeho prvků odpovídá definici jeho konkrétního jazyka – zdali jsou určité prvky v určitých vztazích. Zaručuje korektní zpracování v aplikaci podporující daný jazyk.

### XML namespaces

XML počítá s modularitou, tedy že jeden dokument může používat značky z několika specializovaných (pod)jazyků – např. matematické a chemické vzorce. Namespaces (jmenné prostory) řeší problém konfliktních jmen prvků (více jazyků definujících stejně pojmenovaný prvek). Namespace zahrnuje všechny prvky z jednoho modulu, kompletní identifikace prvku je pak _namespace + prvek_.

Namespace zahrnuje jména prvků a atributů a je identifikován absolutním lokátorem (URI), kvůli jehož velké délce bývá zaveden také prefix. Namespace deklarujeme speciálním atributem prvku a platí pro tento prvek a jeho potomky – nejčastěji vybíráme kořenovým prvek. Atribut `xmlns:prefix="URI"` deklaruje namespace označený daným prefixem, pak můžeme používat jeho prvky pomocí `<prefix:tag />`. Atribut `xmlns="URI"` deklaruje implicitní namespace, který platí pro jména prvků bez prefixu. Atribut bez prefixu patří do stejného namespace jako jeho tag.

### Definice jazyka

#### DTD – Document Type Definition

* Definuje, jaké existují prvky, jaké mají atributy a co mohou obsahovat (tedy i pravidla pro jejich vzájemné vnořování)
* Neumí datové typy – nelze omezit doménu hodnoty atributu nebo obsahu prvku

```xml
<!-- Prvek `alba` obsahuje alespoň jeden prvek `disk` -->
<!ELEMENT alba (disk+)>

<!-- Prvek `disk` má právě jeden prvek `interpret` následovaný právě jedním prvkem `nazev` -->
<!ELEMENT disk (interpret,nazev)>
<!-- Máme k dispozici operátory   ,  *  +  ?  |  a můžeme vnořovat závorky -->

<!-- Prvek `disk` má povinný atribut `id` s textovým obsahem -->
<!ATTLIST disk id CDATA #REQUIRED>

<!-- Prvky `interpret` a `nazev` obsahují text -->
<!ELEMENT interpret (#PCDATA)>
<!ELEMENT nazev (#PCDATA)>
```

* PCDATA (_Parsed Character Data_) je text analyzovaný procesorem – rozpoznávají se prvky, expandují entity, ...
* CDATA (_Character Data_) bere procesor jako textovou konstantu a dál ji neanalyzuje
* DTD ke XML připojíme nejčastěji externě (`<!DOCTYPE alba SYSTEM "cesta/k/souboru.dtd">`), nebo mohou být pravidla uvedena přímo v&nbsp;XML souboru
* Výhodou je široká podpora a jednoduchost
* Nevýhodou je absence datových typů, nepodpora namespaces, syntax

#### XSD – XML Schema Definition

* Specifikace vyvíjená W3C, `xmlns:xs="http://www.w3.org/2001/XMLSchema"`
* Silnější než DTD, kritizováno za složitost
* Má řadu předdefinovaných datových typů a schopnost definovat si vlastní typy
  * Int, decimal, float, double, date, duration, string, ...
  * Nové typy lze definovat restrikcí/spojením/rozšířením existujících typů nebo výčtem přípustných hodnot
  * `<xs:simpleType name="...">` → `<xs:restriction base="xs:string">` → `minLength`/`enumeration`/`pattern`
* Složené datové typy definují vzájemné vztahy jednotlivých prvků
  * _all_ – prvky se vyskytují v libovolném pořadí
  * _sequence_ – prvky se vyskytují v daném pořadí, počet výskytů lze omezit pomocí atributů
  * _choice_ – vyskytuje se jeden z uvedených prvků
  * _sequence_ a _choice_ lze vnořovat

```xml
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
    <xs:element name="alba">
        <xs:complexType>
            <xs:sequence>
                <xs:element name="disk" minOccurs="1" maxOccurs="unbounded">
                    <xs:complexType>
                        <xs:sequence>
                            <xs:element name="interpret" type="xs:string" minOccurs="1" maxOccurs="1"></xs:element>
                            <xs:element name="nazev" type="xs:string" minOccurs="1" maxOccurs="1"></xs:element>
                        </xs:sequence>
                        <xs:attribute name="id" type="xs:string" use="required"></xs:attribute>
                    </xs:complexType>
                </xs:element>
            </xs:sequence>
        </xs:complexType>
    </xs:element>
</xs:schema>
```

Toto schéma je vytvořeno metodou _matrjoška_, kdy se definice prvků do sebe vkládají přímo, stejně jako samotné prvky v příslušném dokumentu. _Matrjoška_ je vhodná pouze pro jednoduchá schémata, pro složitější jazyky ztrácí na přehlednosti a neumožňuje opakovaně využívat dílčí definice. Druhou metodou je _krájení salámu_, kdy se všechny prvky a atributy definují na nejvyšší úrovni a při definici složených typů se na ně odkazuje pomocí `ref="nazev"`. Třetí metodou je _slepý Benátčan_, kdy se globálně definují typy, které se pak využívají při lokální definici prvků a atributů, `type="nazevType"`.

#### Relax NG – Regular Language for XML Next Generation

* Standard od [OASIS](https://en.wikipedia.org/wiki/OASIS_Open)
* Dvě alternativní a vzájemně převoditelné syntaxe: XML a compact (podobné JSONu)
* Postaveno na vzorech, nikoliv datových typech
  * Základní vzory `element`, `attribute`, `text`, `empty`
  * Opakování pomocí `optional`, `zeroOrMore`, `oneOrMore`
    * Nelze snadno určit konkrétní rozsah pro počet opakování, nutno vyjádřit explicitně; v praxi moc nevadí
  * `choice` (buď a nebo), `group` (zachová pořadí, implicitní), `interleave` (libovolné pořadí)
* Datové typy se zpravidla importují z externí knihovny, např. XSD; umožňuje podobné odvozování nových typů
* Umožňuje vytvářet pojmenované vzory, které lze znovupoužít pomocí `<ref name="jmeno" />`

```xml
<element name="alba" xmlns="http://relaxng.org/ns/structure/1.0">
    <oneOrMore>
        <element name="disk">
            <attribute name="id">
            <element name="interpret">
                <text />
            </element>
            <element name="nazev">
                <text />
            </element>
        </element>
    </oneOrMore>
</element>
```

### Validace dokumentu

Program `xmllint` lze použít pro kontrolu, zdali je daný dokument _well-formed_ i _valid_. Podporuje DTD, XSD, Relax NG XML, ...
